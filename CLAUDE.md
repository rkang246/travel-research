# Travel Discovery repo

Destination research catalogs, one folder per trip under `trips/`.

- **Run research:** the `travel-discovery` skill
  ([`.claude/skills/travel-discovery/SKILL.md`](.claude/skills/travel-discovery/SKILL.md)).
- **Source of truth:** `trips/<slug>/data.json`. Its schema is in
  [`references/schema.md`](.claude/skills/travel-discovery/references/schema.md).
  `index.html`, `locations.csv`, `locations.kml`, and `mymaps/` are generated, so never
  edit them by hand. Edit `data.json` and run
  `python3 scripts/build.py trips/<slug> [--geocode]`.
- **Root `index.html` and the README trip table** are regenerated by every build
  (or by `python3 scripts/build.py --index-only`).
- **Report UI** lives in `scripts/report_template.html`, which is a template with
  `__DATA__` / `__TITLE__` placeholders. Changing it changes every trip on the next build.
- **Item IDs are stable keys.** Users' shortlists (`selections.json`) reference
  them, so when refreshing a trip keep existing IDs for items that persist.
- **Ad hoc additions:** `python3 scripts/find.py trips/<slug> "<name>" ...` checks
  whether something is already in the research (or was rejected). Evaluate it
  with the user before adding anything. See *Ad hoc additions* in the skill.
- **Itinerary phase (separate):** reads `data.json` + `selections.json` from
  the trip folder. Discovery research should never prune items for schedule
  reasons.
- **Publishing:** commit locally. Push only when the user asks, because GitHub Pages
  makes reports public if the repo is public.
